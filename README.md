# nanoTabICL training

A short, readable codebase for pre-training a [TabICLv2](https://arxiv.org/abs/2602.11139)-like model on CPU or GPU,
with synthetic datasets generated on the fly by CPU workers.
It extends [nanotabicl](https://github.com/soda-inria/nanotabicl) (model + prior) with the missing pieces from the
[full TabICL repository](https://github.com/soda-inria/tabicl), stripped down to the "nano" essentials.

| File | Content |
|---|---|
| `nanotabicl/model.py` | TabICLv2 architecture (RoPE, QASSMax, induced column attention, ...) |
| `nanotabicl/runtime.py` | Shared model construction and device selection for training and inference |
| `nanotabicl/prior.py` | Simplified TabICLv2 prior: random graphs of random functions producing one dataset |
| `nanotabicl/data.py` | Dataset post-processing and an infinite `DataLoader` of micro-batches generated by CPU workers |
| `nanotabicl/train.py` | Training loop: gradient accumulation, AMP, warmup + cosine schedule, checkpointing, logging |
| `nanotabicl/muon.py` | Muon optimizer, applied to all parameters |
| `nanotabicl/interface.py` | scikit-learn `NanoTabICLClassifier` / `NanoTabICLRegressor` sharing the prior's preprocessing |
| `nanotabicl/config.py` | Nested dataclasses; OmegaConf merges YAML files and `key.subkey=value` overrides |
| `nanotabicl/eval.py` | In-context prediction on small scikit-learn datasets to sanity-check a checkpoint |
| `configs/` | `small.yaml` (CPU development), `classification.yaml` and `regression.yaml` (TabICLv2 size) |

## Usage

```bash
pip install -e .                      # torch, numpy, scikit-learn, omegaconf

python -m nanotabicl.train configs/small.yaml                          # CPU-sized run, ~10 min
python -m nanotabicl.train configs/classification.yaml data.num_workers=16   # TabICLv2 classifier, stage 1
python -m nanotabicl.train configs/classification.yaml configs/stage2.yaml \
    init_from=runs/classification/latest.pt out_dir=runs/classification_stage2  # stage 2, then stage3.yaml alike
python -m nanotabicl.train configs/regression.yaml                     # 999 quantiles + pinball loss
python -m nanotabicl.eval runs/small/latest.pt                         # accuracy / R^2 on real datasets
```

Several YAML files are merged left to right, then `key.subkey=value` overrides are applied. The defaults in
`config.py` are the TabICLv2 stage-1 recipe (`scripts/train_v2_*_stage1.sh` in the TabICL repository): 500K Muon steps
with lr 8e-4 on batches of 64 datasets with 1024 rows, 30-90% training rows and 1-100 features. `stage2.yaml` and
`stage3.yaml` overlay the longer-context stages and are started from the previous stage via `init_from`.

Training resumes automatically from `out_dir/latest.pt` if it exists. The resolved config is saved to
`out_dir/config.yaml`, metrics are printed and appended to `out_dir/metrics.jsonl`; set `wandb_project` to also log to
Weights & Biases.

```python
from nanotabicl import NanoTabICLClassifier, NanoTabICLRegressor
clf = NanoTabICLClassifier(model="runs/small/latest.pt", n_estimators=8).fit(x_train, y_train)
proba = clf.predict_proba(x_test)  # numeric features, NaNs allowed; averages 8 random feature/class orders
reg = NanoTabICLRegressor(model="runs/reg/latest.pt").fit(x_train, y_train)
quantiles = reg.predict_quantiles(x_test, alphas=(0.1, 0.5, 0.9))  # reg.predict gives the median
```

## How it works

- **Data.** Each `DataLoader` worker produces micro-batches of `data.micro_batch_size` datasets that share the number of
  rows, features and training rows (sampled per micro-batch), so no padding across datasets is needed.
  Each dataset comes from `prior.py`; `data.py` then permutes labels, rejects datasets whose train and test rows do
  not contain the same classes, clips outliers and standardizes with statistics of the training rows (features that
  are constant there become zero), and permutes features. The scikit-learn interface applies the same
  `preprocess` function and averages predictions over seeded random feature (and class) orders.
  Optionally, datasets on which ExtraTrees does not beat the mean predictor are rejected as well.
- **Training.** One Muon step accumulates gradients over `optim.accum_steps` micro-batches of `data.micro_batch_size`
  datasets. All parameters are
  optimized by Muon (reshaped to 2D), with the step size scaled to the RMS of an AdamW update, as in the TabICL code.
  The schedule is linear warmup followed by cosine decay to zero.
  Classification uses cross-entropy over `max_classes` logits; regression predicts `n_quantiles` quantiles of the
  standardized target and uses the pinball loss. Mixed precision via `torch.autocast` is available with `optim.amp_dtype: bfloat16` (the recipe uses float32).
- **Config.** `Config` nests `ModelConfig`, `DataConfig` and `OptimConfig`. `load_config` uses OmegaConf to merge YAML
  files and `key.subkey=value` overrides onto the defaults with type conversion and unknown-key errors.

## Simplifications compared to the full TabICL training code

No distributed (multi-GPU) training, no AdamW option, no pre-generated prior data on disk, no FlashAttention-3,
no gradient checkpointing, no correlated hyperparameter sampling within a batch, only one learning rate schedule
(cosine to 0 instead of 1e-7), and the prior standardizes with training-row statistics (TabICL uses all rows).
See the nanotabicl README for the differences between the nano prior and the full TabICLv2 prior.
